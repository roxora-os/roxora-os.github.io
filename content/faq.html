Why not ubuntu-rockchip?

The ubuntu-rockchip project built Ubuntu images for many RK35xx boards. Its repository has been archived on GitHub and no longer receives updates.

Roxora does not maintain kernels of its own. The kernel, device tree, U-Boot and firmware come from Armbian, which keeps them current for a long list of boards, and everything else comes from Ubuntu.

Why not Armbian’s own images?

Armbian’s images put Armbian’s own userland on top of its hardware support: a first-run wizard, a config tool, its own login messages, RAM logging and zram defaults, and its own apt setup. Some people just want plain Ubuntu on the board.

Roxora keeps only Armbian’s hardware packages and replaces the rest with what Ubuntu ships, so the system looks and updates like any other Ubuntu install. If you want Armbian’s tools and defaults, Armbian’s own images are the right choice.

Is hardware video decoding or NPU acceleration supported?

Not in the way some earlier Rockchip images provided it. On Armbian’s vendor kernel, the userspace that drove the vendor video and NPU blocks came from third-party PPAs. Roxora installs nothing from third-party PPAs, so that acceleration is not provided.

The images use Armbian’s edge kernel, which follows mainline. Graphics and video use the upstream Mesa and V4L2 stack that Ubuntu ships in its archive. What that covers depends on how far mainline support for each SoC has come.

Where do updates come from?

Userspace updates come from the Ubuntu archive, as on any Ubuntu install. The kernel, device tree, U-Boot and firmware packages come from Armbian’s repository. apt is pinned so that only those hardware packages are taken from Armbian; everything else is ignored there.

Does Roxora run on a Raspberry Pi?

No. Roxora images are for the Rockchip boards on the Boards page. Raspberry Pi Imager can write them to a card, but they do not boot on a Raspberry Pi.
